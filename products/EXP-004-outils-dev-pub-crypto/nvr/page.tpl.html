NuGet version range checker

Type the Version of a <PackageReference> such as [1.0,2.0), 1.*, 1.0.0-* or 1.0, and the versions published for that package. You see which versions match, in plain words, and which one dotnet restore will pick. The page runs a JavaScript copy of NuGet's own version code (NuGet.Versioning), checked against the real library and against real dotnet restore runs.

The surprise: NuGet picks the lowest match

npm, Cargo, pip and Maven take the highest version that matches a range. NuGet takes the lowest one (“lowest applicable version”). So [1.0,2.0) does not mean “the newest 1.x”: it means “1.0.0 if it exists”. For the newest 1.x, write a floating version: 1.*. How NuGet orders versions

A NuGet version has 3 or 4 numbers (1.2.3.4; missing ones are 0, so 1.0 = 1.0.0 = 1.0.0.0), then an optional prerelease label after - and optional build metadata after +. A prerelease is lower than the same version without label: 2.0.0-rc.1 < 2.0.0. Labels are compared part by part (split at dots): numbers as numbers (beta.2 < beta.10), words alphabetically and case-insensitively (RC = rc, unlike npm). Build metadata is ignored.
