Documentation

An MCP server that tells an AI assistant which version a dependency constraint really installs today, using the exact rules of each package manager: npm, Cargo, Composer, pip, RubyGems, Maven, Gradle, NuGet. It reads the published versions live from npmjs, crates.io, Packagist, PyPI, RubyGems, Maven Central and NuGet (read-only, no key).

Why: the same text means different things. [1.0,2.0) takes 2.0-rc1 in Maven but not in Gradle; 1.0 means "1.0 or higher, lowest wins" in NuGet; ^0.2 stops before 0.3.0. Assistants often guess these rules wrong.

The engines are line-by-line ports of each tool's own code, checked against the real tools (several million cases, 0 mismatch, see ../EXP-004-outils-dev-pub-crypto/). No key, no dependency. Only resolve_from_registry uses the network.

Tools

  • resolve_from_registry(ecosystem, package, constraint) → the version installed today, the newest published one, and the 10 newest that match. Example: pip, requests, ~=2.31 → 2.34.2.
  • check_version_constraint(ecosystem, constraint, versions) → for each version: accepted or not; plus the version the tool would pick.
  • compare_across_ecosystems(constraint, versions) → the same constraint in every package manager, grouped by identical result.
  • sort_versions(ecosystem, versions) → versions in that tool's order.

Install

  • Claude Desktop, one click: download version-range-mcp-1.2.0.mcpb and open it.
  • Docker (any MCP client):
{ "mcpServers": { "version-range": { "command": "docker", "args": ["run", "-i", "--rm", "ghcr.io/lawatch/version-range-mcp:1.2.0"] } } }
  • Node 18+, no Docker: copy this folder, then
{ "mcpServers": { "version-range": { "command": "node", "args": ["/path/to/server.js"] } } }

Example

Ask your assistant: "Which Guava version does [32.0,33.0) give me in Maven?" → 32.1.3-jre (newest published: 33.8.0-jre). Or: "Does Maven's [1.0,2.0) accept 2.0-rc1? And Gradle's?" → Maven: yes. Gradle: no.
