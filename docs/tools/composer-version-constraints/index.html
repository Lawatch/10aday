Composer version constraints: what ~1.2, ^1.2, 1.2.* and "1.2" really allow in composer.json

Short answer: in composer.json, ^1.2.3 allows ≥1.2.3 <2.0.0 (like npm). The tilde lets the last number you wrote move: ~1.2 = ≥1.2.0 <2.0.0, ~1.2.3 = ≥1.2.3 <1.3.0. A bare version is exact, even a partial one: "1.2" means 1.2.0 only. Those last two rules are where people coming from npm get surprised.

Rules of thumb for composer.json

  • Use ^ by default (composer require writes it for you): it follows semantic versioning, including the 0.x rule.
  • Use ~ with three numbers (~1.2.3) to allow patch updates only. With two numbers it behaves like Ruby's ~> and pip's ~=: see ~> vs ~= vs ~.
  • Never write a bare partial version ("1.2") expecting a range: it is an exact pin on 1.2.0.

Common questions

What does ~1.2 mean in composer.json?

≥1.2.0 and <2.0.0: the last number you wrote (2) may increase. npm and Cargo read the same ~1.2 as ≥1.2.0 <1.3.0. Write ~1.2.0 in Composer if you want patch updates only.

What is the difference between ^ and ~ in Composer?

With three numbers: ^1.2.3 = ≥1.2.3 <2.0.0 and ~1.2.3 = ≥1.2.3 <1.3.0. With two numbers they are the same for 1.x and above: ^1.2 = ~1.2 = ≥1.2.0 <2.0.0. Below 1.0 they differ: ^0.3 = <0.4.0 but ~0.3 = <1.0.0.

Does "1.2" in composer.json mean 1.2.x?

No. A bare version without an operator or wildcard is an exact constraint, padded with zeros: "1.2" matches 1.2.0 only. Write "1.2.*" for the whole 1.2.x line. (In npm, a bare 1.2 means 1.2.x.)

How do I write "and" and "or" in Composer?

A space or a comma means “and” (>=1.2 <2.0 or >=1.2,<2.0); || means “or” (^1.2 || ^2.0). Hyphen ranges like 1.2 - 2.3 include the whole 2.3.x line.
