~> vs ~= vs ~: the “pessimistic” operator in five package managers

RubyGems (~>, the “pessimistic” or “twiddle-wakka” operator), pip (~=, “compatible release”) and Composer (~) share one rule: the last number you wrote may increase, the ones before it are fixed. npm and Cargo use ~ differently: they always keep the minor number when you give one. So the “same” constraint on 1.2 means <2.0 in three tools and <1.3 in the other two.

Which one should I write?

  • To allow patch updates only, write three numbers everywhere: ~> 1.2.3, ~=1.2.3, ~1.2.3. All five tools agree: ≥1.2.3 <1.3.0.
  • To allow minor updates, prefer the caret in npm, Cargo and Composer (^1.2), and the two-number form in RubyGems and pip (~> 1.2, ~=1.2). See tilde vs caret.

Common questions

What does ~> mean in a Gemfile?

~> 2.1 means ≥2.1 and <3.0; ~> 2.1.0 means ≥2.1.0 and <2.2. RubyGems drops the last number you wrote and bumps the one before it. It is called the pessimistic version constraint.

What does ~= mean in requirements.txt?

It is the PEP 440 compatible release operator. ~=1.4.2 means ≥1.4.2 and ==1.4.*; ~=1.4 means ≥1.4 and ==1.* (so <2.0). ~=1 is invalid: it needs at least two numbers.

Is pip ~= the same as npm ~?

Only with three numbers. ~=1.4.2 and npm ~1.4.2 both mean ≥1.4.2 <1.5.0. With two numbers they differ: pip ~=1.4 allows up to <2.0, npm ~1.4 stops before 1.5.0.

Can I write ~> in package.json?

npm accepts ~> and reads it as its own tilde, so ~> 1.2 in package.json means ≥1.2.0 <1.3.0, not the RubyGems meaning (<2.0). Cargo and Composer reject ~>.
