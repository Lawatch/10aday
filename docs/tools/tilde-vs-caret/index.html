Tilde (~) vs caret (^): what each one allows in npm, Cargo and Composer

Short answer: the caret ^ allows every update that does not change the first non-zero number; the tilde ~ allows patch updates only, when you write a patch number. ^1.2.3 = ≥1.2.3 <2.0.0 and ~1.2.3 = ≥1.2.3 <1.3.0 in npm, Cargo and Composer alike. The trap is the two-number tilde: ~1.2 stops before 1.3.0 in npm and Cargo, but allows every 1.x from 1.2 in Composer.

How to remember it

  • Caret ^: “compatible with” — keep the leftmost non-zero number, let everything to its right move.
  • Tilde ~ in npm and Cargo: “approximately” — keep major and minor, let the patch move (with ~1, keep the major).
  • Tilde ~ in Composer: let the last number you wrote move. ~1.2 → any 1.x ≥ 1.2; ~1.2.3 → any 1.2.x ≥ 1.2.3. This is the same rule as Ruby's ~> and pip's ~=: see ~> vs ~= vs ~.

Common questions

What is the difference between ~ and ^ in package.json?

~1.2.3 accepts patch updates only (≥1.2.3 <1.3.0). ^1.2.3 also accepts minor updates (≥1.2.3 <2.0.0). npm writes ^ by default when you run npm install.

Why does ^0.2.3 not accept 0.3.0?

Below 1.0.0 the caret locks the first non-zero number. ^0.2.3 means ≥0.2.3 <0.3.0 and ^0.0.3 means ≥0.0.3 <0.0.4, in npm, Cargo and Composer.

Does ~1.2 mean the same in Composer and npm?

No. In npm and Cargo ~1.2 means ≥1.2.0 <1.3.0. In Composer the last number you wrote may move, so ~1.2 means ≥1.2.0 <2.0.0. Write ~1.2.0 in Composer if you want patch updates only.

What does a bare version like "1.2.3" mean in Cargo.toml?

In Cargo a bare version is a caret requirement: serde = "1.2.3" means ^1.2.3 (≥1.2.3 <2.0.0). In npm and Composer the same string means exactly 1.2.3. Use =1.2.3 in Cargo to pin.
