Does ^1.2.0 match 1.3.0-beta? Pre-release versions in five package managers

Short answer: no, not by default. All five package managers skip pre-releases (-beta, -rc, b1, .rc1) unless you ask for them. But “asking” works differently in each one. Put a pre-release in the constraint, and npm and Cargo only open the door for that exact x.y.z. Composer, pip and RubyGems then accept any newer pre-release. And in RubyGems, < 2 lets 2.0.0.rc1 through.

Have a constraint and a list of versions? Paste them into the Version Constraint Checker: it shows, side by side, what npm, Cargo, Composer, pip and RubyGems accept.

The rule in each package manager

  • npm: a pre-release matches only if a comparator in the same range has a pre-release on the same major.minor.patch. So >=2.0.0-rc.1 accepts 2.0.0-rc.2, but never 2.1.0-beta.1.
  • Cargo: the same idea. A pre-release is only selected when the requirement names one, and only on that major.minor.patch.
  • Composer: the constraint itself does include pre-releases (^1.2.0 means ≥1.2.0.0-dev). It is minimum-stability, stable by default, that filters them out. A flag such as @beta, or a -beta1 in the constraint, lowers it for that package.
  • pip (PEP 440): pre-releases are skipped unless the specifier names one, you pass --pre, or only pre-releases match. <2.0 never matches 2.0rc1.
  • RubyGems / Bundler: pre-releases are skipped unless the requirement names one or you pass --pre. Once they are allowed, plain version order applies: 2.0.0.rc1 is below 2.

Common questions

Does ^1.2.0 match 1.3.0-beta.1 in npm?

No. In npm a pre-release only matches if the range itself contains a pre-release on the same major.minor.patch. ^1.2.0-beta.1 matches 1.2.0-beta.2 but still not 1.3.0-beta.1. Cargo follows the same rule.

How do I install a beta or release candidate?

npm and Cargo: write it in the constraint, e.g. ^2.0.0-rc.1. Composer: ^2.0@RC, a constraint with -RC1, or "minimum-stability". pip: pip install --pre or a specifier that names a pre-release, e.g. >=2.0.0rc1. RubyGems: gem install --pre or a requirement such as >= 2.0.0.rc1.

Why did pip install a release candidate I did not ask for?

pip accepts a pre-release when no final release satisfies the specifier. With 1.2.5 and 2.0.0rc1 published, >1.2.5 installs 2.0.0rc1. Composer, npm, Cargo and RubyGems install nothing in that case.

Does <2.0.0 include 2.0.0-rc.1?

Not in npm, Cargo, Composer or pip (PEP 440 says <V excludes pre-releases of V). In RubyGems, 2.0.0.rc1 sorts below 2.0.0, so < 2 accepts it as soon as pre-releases are allowed.

Why does Composer ^1.2.0-beta1 install 1.3.0-beta1?

Writing -beta1 in a root requirement sets the stability for that package to beta. Every beta in the range is then allowed, and Composer takes the highest one. Use "prefer-stable": true to keep stable releases when one fits.
