Wildcards (x, *), hyphen ranges and ||: npm range syntax next to Cargo, Composer, pip and RubyGems

Short answer: in npm, 1.x = 1.* = 1 = ≥1.0.0 <2.0.0; 1.2.3 - 2.3.4 includes both ends; a hyphen range with a partial upper bound (1.2 - 2.3) includes the whole 2.3.x line; || means “or”; a space means “and”. Cargo has no hyphen ranges and no || and uses a comma for “and”. Composer copies most of npm's syntax but reads partial versions as exact ones: 1.2 || 3 means “1.2.0 or 3.0.0”, and >1.2 already accepts 1.2.1.

Common questions

What does 1.x mean in package.json?

1.x, 1.* and a bare 1 all mean ≥1.0.0 <2.0.0 in npm. 1.2.x means ≥1.2.0 <1.3.0. A lone * or x means any release version.

Are npm hyphen ranges inclusive?

Yes. 1.2.3 - 2.3.4 means ≥1.2.3 ≤2.3.4. If the upper bound is partial, every version it names is included: 1.2 - 2.3 means ≥1.2.0 <2.4.0, so 2.3.9 matches.

How do I write "and" and "or" in a version range?

npm: a space is “and” (>=1.2 <2), || is “or”. Composer: space or comma for “and”, || for “or”. Cargo, pip and RubyGems: comma for “and”, no “or” at all.

Does >1.2 accept 1.2.5?

Not in npm or Cargo: a partial version stands for the whole 1.2.x line, so >1.2 starts at 1.3.0. In Composer, >1.2 means >1.2.0, so 1.2.5 matches. Write three numbers to avoid the ambiguity.
