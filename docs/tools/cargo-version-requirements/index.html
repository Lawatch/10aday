Cargo.toml version requirements: what "1.2.3", ^, ~, * and = really allow

Short answer: in Cargo.toml a bare version is a caret requirement: serde = "1.2.3" allows ≥1.2.3 <2.0.0, and rand = "0.8.5" allows ≥0.8.5 <0.9.0. To pin one version, write "=1.2.3". npm reads the same bare string as an exact version, which is why copying requirements between package.json and Cargo.toml changes their meaning.

Rules of thumb

  • Writing "1.2.3" in Cargo.toml is a minimum with caret updates, not a pin. Your Cargo.lock is what pins.
  • For a 0.x crate, every minor bump is breaking for Cargo: "0.8" never upgrades you to 0.9.
  • ~ in Cargo behaves like npm's tilde, not like Composer's or Ruby's ~>: see tilde vs caret and ~> vs ~= vs ~.

Common questions

What does serde = "1.0" mean in Cargo.toml?

It is the caret requirement ^1.0: any version ≥1.0.0 and <2.0.0. Cargo will pick the newest compatible 1.x release when it resolves the lock file.

How do I pin an exact version in Cargo.toml?

Write "=1.2.3". Note that "=1.2" is not exact: it allows every 1.2.x (≥1.2.0 <1.3.0).

Why does "0.8.5" not accept 0.9.0 in Cargo?

Below 1.0.0 the caret keeps the first non-zero number fixed, because Cargo treats a 0.x minor bump as breaking. "0.8.5" = ≥0.8.5 <0.9.0 and "0.0.3" = exactly the 0.0.3 line (<0.0.4).

Does Cargo support || or hyphen ranges?

No. Cargo rejects || and 1.2 - 2.3. Combine comparisons with a comma instead: ">=1.2, <1.5".
