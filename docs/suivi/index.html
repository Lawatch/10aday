Une bibliothèque Go pour lire les plages de versions NuGet, Gradle et Maven

Un petit programme que d'autres programmes utilisent pour savoir si une version de logiciel est acceptée par une règle (« entre 1.0 et 2.0 »). Il est diffusé par le registre du langage Go, qui n'exige aucun compte. But : nos premiers utilisateurs venus sans Google, et des liens vers nos pages.

Déjà fait
Rien encore côté Go. La logique existe déjà en JavaScript, testée contre les vrais outils (pages NuGet, Gradle et Maven de l'ancienne piste EXP-004).
Résultat
Le 13/11, le registre Go ne renvoie aucun résultat pour « nuget version range », « gradle version range » et « maven version range ». La place est libre.
Bloqué par
rien.
Prochaine étape
Écrire le paquet NuGet en Go, le tester contre le vrai outil .NET, puis le faire apparaître sur pkg.go.dev.
Décision
le 20/11 (dans 7 jours). On arrête si : Le 20/11, le paquet n'apparaît pas dans la recherche de pkg.go.dev, ou aucun signal extérieur (aucun projet qui l'utilise, 0 étoile, 0 visite venue du registre).

Un outil pour les assistants IA qui dit quelle version d'une bibliothèque sera installée

Les assistants IA (Claude, Copilot…) se trompent souvent sur les règles de versions des bibliothèques. On leur donne un outil branchable, inscrit au registre public de ces outils, et on compte combien de fois il est téléchargé.

Déjà fait
L'outil est écrit et testé (27 vérifications, toutes bonnes). Il couvre 8 gestionnaires de bibliothèques. Il n'est pas encore publié.
Résultat
0 téléchargement au 13/11 : pas encore publié.
Bloqué par
La publication automatique a été refusée le 13/11 par le filtre de sécurité de la session. Elle attend un accord explicite.
Prochaine étape
Obtenir l'accord de publier, activer la publication, puis vérifier que l'outil apparaît dans le registre public.
Décision
le 20/11 (dans 7 jours). On arrête si : Moins de 5 téléchargements le 20/11, ou publication toujours impossible le 15/11.
